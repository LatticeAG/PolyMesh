# PolyMesh architecture

PolyMesh is organized as a local-first task exchange. A broker owns a session and routes bounded protocol records between agents; agents own their capability handlers and authorization decisions.

```text
                         ┌───────────────────────────────┐
                         │       Application code         │
                         │  capability handler / caller   │
                         └───────────────┬───────────────┘
                                         │
                         ┌───────────────▼───────────────┐
                         │        Application layer       │
                         │ task lifecycle, contracts,     │
                         │ policy, result validation      │
                         └───────────────┬───────────────┘
                                         │
                         ┌───────────────▼───────────────┐
                         │         Envelope layer         │
                         │ strict JSON records, IDs,      │
                         │ deadlines, delivery metadata   │
                         └───────────────┬───────────────┘
                                         │
                         ┌───────────────▼───────────────┐
                         │        Handshake layer         │
                         │ hello, card, auth, ready       │
                         └───────────────┬───────────────┘
                                         │
                         ┌───────────────▼───────────────┐
                         │         Framing layer          │
                         │ bounded text frames, strict    │
                         │ parsing, size limits           │
                         └───────────────┬───────────────┘
                                         │
                         ┌───────────────▼───────────────┐
                         │       Transport layer          │
                         │ loopback WS or enrolled WSS    │
                         └───────────────────────────────┘
```

## Main components

```text
  Alice application                         Bob application
         │                                         │
         ▼                                         ▼
  @latticeag/polymesh-client           @latticeag/polymesh-client
         │                                         │
         └────── secure session / task records ───┘
                            │
                            ▼
                 @latticeag/polymesh-broker
                    session + routing owner
                            │
          ┌─────────────────┴──────────────────┐
          ▼                                    ▼
  @latticeag/polymesh-gateway          optional constrained
  Node REST/SSE adapter                 mDNS discovery hints
```

The gateway is an adapter around broker semantics. It is not a hosted relay, durable cloud service, or substitute for the broker's task ownership rules.

```text

       │                 │
@latticeag/              @latticeag/

       ▲
       │

latticeag-polymesh (Python distribution, imported as `polymesh`)
       └── v0.1 SDK surface and shared compatibility fixtures
```

The TypeScript client and gateway depend on the broker package for shared protocol types and validation. A project generated by the quick-start generator depends on the published broker and client packages; it does not rely on workspace-only import aliases.

## When to use each package

| Need | Use |
| --- | --- |
| Route local agents or own session admission | `@latticeag/polymesh-broker` |
| Implement an agent, call a capability, or use the CLI | `@latticeag/polymesh-client` |
| Expose the existing REST/SSE task observation adapter in a Node process | `@latticeag/polymesh-gateway` |
| Start a minimal safe local project | `@latticeag/create-polymesh-app` |
| Build against the v0.1 Python SDK surface | `latticeag-polymesh`, imported as `polymesh` |

Choose the broker for connection/session routing, the client for agent behavior, and the gateway only when the Node HTTP adapter fits the bounded REST/SSE use case. Do not use the gateway to infer hosted durability, general streaming, or remote relay support.

## Transport boundary

The local development profile is intentionally restrictive: plaintext WebSocket is accepted only with explicit opt-in on a numeric loopback endpoint and a runtime token. A normal container service hostname, LAN address, or Internet endpoint is not loopback. For remote use, select and correctly configure the enrolled WSS profile; this repository does not ship a managed deployment.
